키워드 하나로 HR 인사이트 워크플로우 설계

WORKFLOW

HR·리더십 키워드 하나를 입력하면 정리된 인사이트 자료를 산출해 → Slack의 팀 Canvas 반영 → 지정 채널 메시지 알림으로 이어지는 워크플로우를 자동화

QUESTION   질문

반복되는 리서치·구조화·Slack 공유·콘텐츠 활용 제안을 재사용 가능한 스킬로 결과 편차를 줄이고 팀내 신속하게 전달할 수 있을까?

CONTEXT   문제 상황

팀에서 만드는 콘텐츠가 많다보니 마케터도 늘 일이 많고 디자이너인 저도 일이 많아 양질의 콘텐츠 발굴을 위한 소스를 보다 잘 정리하고 공유하는 것이 중요한데 그 역할을 할 여력이 있는 사람이 없었음.

TRY   시도

• 실제 필요한 분야의 키워드를 던지고 실전 테스트
• HBR·Gallup·McKinsey 등 신뢰성 높은 아티클과 검증된 통계만 수집
• 강조 부호 제거, 통계 옆 출처 하이퍼링크, 검색결과 URL 금지 등 작성 규칙 고정
• 최신 항목이 Slack Canvas 맨 위에 쌓이도록 반영하고 승인 후 채널 알림 발송
• CANVAS_ID·NOTIFY_CHANNEL·ORG_NAME·SIGNATURE 등 개인·조직 값을 설정 파라미터로 분리, insight-cowork SKILL.md로 문서화·패키징

FRICTION   막힌 지점

검색결과 페이지 URL은 문단의 근거로 쓰기에 부정확한 이슈 발생. 캔버스 ID·채널·발신 명의를 하드코딩하면 보안과 재사용성이 다소 떨어짐.

CHANGE   바꾼 점

Canvas 반영 전 현재 section_id를 읽고 실행 후 다시 검증하는 절차를 넣었습니다. 검색결과가 아니라 문단 주장과 가장 맞는 특정 아티클을 인라인 출처로 배치했고, 개인·조직 값은 설정값으로 분리했습니다. 캔버스 반영과 알림은 반드시 초안 승인 뒤 실행하도록 규칙화했습니다.

LEARNED   배운 점

도구는 문서 설명보다 실제 실행 결과를 재검증해야 했습니다.

실험 2. DESIGN OPS

디자인 요청을 자동으로 관리하는 트래커 구축

2026-07-21
DESIGN OPS

클로드와 슬랙·노션 커넥터를 연결해서(MCP 기반) 만든 자동화 워크플로우 - 접수/분류 /누락 점검/기록/회고까지 자동 처리하는 디자인 요청 트래커를 구축했습니다. 이후 옵시디언도 연결하고 디자인 작업 대시보드도 구성했어요.

QUESTION   질문

디자인 요청을 자동으로 정리하고, 필요한 정보를 빠짐없이 확인하며, 완료 후 회고까지 연결할 수 있을까?

CONTEXT   문제 상황

1)팀별 디자인 요청은 늘 많고 작업기간은 짧은데 슬랙에 들어오는 일을 늘 쳐내기 바쁘고, 일을 구조화하지 못함.
2)분기별 회의 때 완수한 부분과 성과를 정리하는 데 따로 시간을 내어 업무 로드가 생김
3) 막상 업무 요청 내용과 완수한 정량적 수치 산출이 수기로 파악하며 정확도가 떨어져서 성과지표로 당당히 제시를 못함

*결과적으로 일은 늘 많은데 업무에 대한 성과에 대한 근거자료 준비를 하는데 피로하여 성과 어필을 못 하는 경우가 많았음

TRY   시도

데이터 기반 반복 작업 자동화 구조를 만들어 내가 한 업무량과 성과 지표를 언제라도 확인할 자동화 구축했어요.

•Slack: 디자인 요청 수집 및 매일 아침 알림 푸시
•Notion: 트래커 DB 및 대시보드
•Obsidian: 플레이북 · 요청 노트 · 회고 기록
•Gmail: 브리핑 백업 알림(슬랙으로 충분하여 메일은 중단 시킴)

FRICTION   막힌 지점

•초기에 자연어로 프롬프트를 너무 길게 쓰고 오차범위가 커셔 클로드 토큰을 많이 소모함에 따라 원하는 것 구현까지 다소 딜레이가 발생했어요.

•노션은 무료버전 쓰는데 api관련 사용량이 한정되어 원하는 만큼 원하는 대로 구현을 못 한 채 잠시 중단하는 상황 있었습니다.

CHANGE   바꾼 점

•지정한 슬랙 채널에 들어온 디자인 요청부터 완료까지 트래킹과 착수부터 완료까지의 소요시간 측정해 노션에 업무별 대시보드 자동 기록
•업무 분류 · 요청자 · 상태 · 마감희망일 · 배정 스킬 · 누락 자료를 자동 기록하고 착수 전 소통할 것을 빠르게 전달할 수 있게 자동화
•배운 점 · 깨달은 점 · 만족한 점 · 아쉬운 점 · 도움 된 자료/소스 · 성과로 구성한 회고 6항목도 함께 축적하여 매년 면담 시 리플렉션 노트 쓰는 것에 바로 꺼내 활용할 수 있게 함.
•미완료 작업, 마감 임박 작업(D-3), 카테고리별 누적 현황, 분기별 리뷰, 연간 리뷰를 확인하는 라이브 대시보드를 만듦.
•매일 오후 6시에 디자인-완료 이모지와 [디자인 최종 완료] 문구를 감지해 상태를 완료로 바꾸고, 회고가 없는 완료 건만 1회 알림
•웹툰 · 컷만화 · 카드뉴스 · insight-cowork · 일러스트 등 카테고리에 따라 기존 제작 스킬을 자동 연결

*Slack은 입력, Notion은 상태 저장, Obsidian은 규칙 · 플레이북 · 회고, Gmail은 백업 알림으로 역할을 분리했습니다.

LEARNED   배운 점

•반복 업무 자체보다 내가 어떤 지점에서 반복적으로 불편함을 느끼는지 인식하는 것이 더 중요함
•Claude를 단순한 도구가 아니라 역할과 규칙을 명확히 정의한 협업자로 대할수록 결과 품질이 높아진다는 것
•외부 저장소에 규칙과 기록을 축적하면 세션이 바뀌어도 같은 판단 기준으로 업무를 이어갈 수 있음.

캐릭터 개체가 많아질수록 디자인 일관성이 떨어지다 보니 생성형 이미지 캐릭터를 중심으로 테마를 잡고 지속적인 콘텐츠를 쌓아가기가 어렵다.

FRICTION   막힌 지점

•감정캐릭터 종류를 다양하게 하다 보니 감정별 특징요소의 보완이 필요할 때 추가 프롬프트로 수정이 불가피 했고, 힉스필드는 실험해 보고 싶었지만 AI 구독료 부담이 되어 gpt와 gemini로만 실험하게 됨.
•사이클 안내와 동일하게 시도하지 못해 엘리먼트 요소로 등록해 진행하는 일관성은 시도하지
못 함.
•gpt와 gemini 프롬프트 생성으로는 다소 털 재질과 체형이 달라지고 색이 흔들렸습니다.

CHANGE   바꾼 점

한 컷에 3×4 세트를 한 번에 생성하고 HEX 색상값을 지정했습니다.

LEARNED   배운 점

LEARNED   배운 점

QUESTION   질문

전문 자료를 출처를 보존하면서 재사용 가능한 흐름으로 만들 수 있을까?

CONTEXT   문제 상황

•교육 서비스 회사이지만 연구소로서 전문자료를 발굴하고 현업의 전문적 소양과 안목을 높여 고객사와의 소통과 제안서 작성 시 활용해 경쟁사와의 차별성을 키워야 함.
•특히 B2B팀은 대기업을 상대로 소통해야 하고 세미나를 많이 열기 때문에 각 담당자의 전문 지식과 소양이 매우 중요한데 아직 AX에 숙달이 안 되어 업무 시간이 빠듯

FRICTION   막힌 지점

MCP 서버 실행과 앱에서 실제 도구를 연결하는 일을 처음에는 같은 것으로 생각했습니다.

CHANGE   바꾼 점

원문은 Zotero, 분석과 활용 기록은 Notion으로 역할을 구분했습니다.

LEARNED   배운 점

업무에 필요한 MCP를 찾아내는 것부터 실무 연관도 높은 MCP로 업무를 다양한 방식으로 시스테믹하게 할 수 있다는 경험, AI 자동화를 계속 시도하고 싶은 의지와 자신감을 얻고 배웠어요.
